1. SOURCE PRESERVATION AND SPEAKER REVIEW
Preserve raw segment IDs, original input order, speaker IDs, text, timestamps, and any actual ASR confidence without alteration. Keep confidence null if unavailable. Add stable adapter IDs only when absent, documenting their origin. Never overwrite the raw transcript when editing text or attribution; save a separately versioned reviewed record and an edit audit trail.

2. CANONICAL RECORD AND MAPPING CONTRACT
Use an existing runtime schema validator. If the backend is Python and no equivalent already exists, Pydantic is a suitable small addition. Validate nested types and forbid unexpected keys at the input boundary. Schema validity does not prove factual correctness: separately validate all source references and review rules.
Implement these logical types, adapting names to the app:
- SourceSegment: segment_id, speaker_id, start_ms, end_ms, exact text, asr_confidence (nullable). Require stable unique IDs; known end >= start; confidence, if present, within its documented scale.
- EvidenceRef: segment_id, speaker_id, start_ms, end_ms, quote. Each reference must resolve to its immutable segment. A quote must match the referenced text or a verified exact substring, with offsets when using a substring. Timestamps must match the source, not a model invention.
- ReviewedField<T>: value (T or null), source_type (transcript, session_metadata, manual, unknown), source_refs, review_status (missing, proposed, reviewed, conflict), reviewed_by, reviewed_at. Record the metadata key for session_metadata and the authenticated actor/revision for manual changes. Never fabricate review actors, dates, or approvals.
- Participant: person_id, reviewed name, reviewed role. Keep extra identity fields out unless the real form requires them.
- SpeakerBinding: speaker_id, person_id or null, scope (whole session or specified segments), confirmation_status, confirmed_by, confirmed_at.
- ReviewedTurn: turn_id, segment_ids, speaker_id, kind (question, answer, statement, unclassified), original_text, optional reviewed_text, source_refs, review_status. original_text remains source-exact; human corrections are separate and auditable.
- QALink: question_turn_ids, answer_turn_ids, confirmation status and reviewer. Allow one question with multiple answer turns, multiple questions, interruptions, and unpaired statements. Never manufacture a question or assume consecutive speech is a question/answer pair.
- ReviewRecord: source transcript ID and digest, template ID/version/classification, revision, fields, participants, speaker bindings, ordered turns, QA links, issues, human-only sections, audit log, and approval bound to that exact revision/digest.
Each populated field needs valid evidence or a documented manual/session-metadata origin. Missing values stay null. Contradictions keep the conflicting candidates and their evidence; do not choose the latest or most confident claim automatically. Reviewer resolution is explicit and auditable. Requiredness is template configuration, not a guessed legal rule. Derived render variables such as investigator_name and statement_giver_names come only from confirmed participant records, not extra model-generated facts.
Create a small declarative mapping configuration: template placeholder -> canonical JSON path or reviewed renderer, required/optional, allowed source types, human-only flag, and display formatting. The fallback’s minimum required-for-reviewed-export inputs are subject, confirmed speaker bindings and roles, and reviewed included turns. Names and other fields follow a configurable policy; unknown names must never be invented. Show every missing configured requirement.
