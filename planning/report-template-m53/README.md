# Model م ٥٣: current application form and review samples

**Current implementation:** `central/backend/app/services/report_m53.py` and the structured
form in the report composer. See `docs/m53-report-form.md` for the workflow and limitations.

**Current review files:** `runtime-review/m53-runtime-blank.pdf`,
`m53-runtime-filled.pdf`, and `m53-runtime-long.pdf` (3, 3 and 4 pages), with matching DOCX,
layout JSON, page images and `verification.json`. These are generated by the application
renderer using fictional values. `runtime-word-check/` independently verifies that Word
can open and export these files with the embedded Arabic fonts and without character loss.

`source-structure/` contains the intermediate source-faithful Word specimens. The earlier
redesigned `output/` examples below are **superseded** and are not the application's form.

Generate the current samples with `build_runtime_samples.py`; verify them with
`verify_runtime_samples.py`. `verify_runtime_samples.py --word` checks the independent
Word exports against the same per-page layout. These checks verify character preservation
and page counts, not exact OCR order or institutional approval.

The blank Word document is a human-editable working form. It is **not yet an upload-ready
template for the existing report engine**: placeholder mapping and integration are a
subsequent task. The existing active template and finalized reports remain unchanged.

## Layout decisions to review

- A4; 15 mm side margins; 34 mm right-hand margin column and 146 mm text column.
- First-page institutional/title block; compact continuation heading on later pages.
- Repeated `هامش` table header, flowing paragraphs and no hard-coded page count/page breaks.
- Labels follow their associated rows. Short source paragraphs stay together; a single
  statement can span multiple rows and pages without repeating its speaker attribution.
- Automatic `PAGE` and `NUMPAGES` fields, including first-page footer.
- Editable Arabic paragraphs/tables; no rasterized page backgrounds or embedded signatures.
- `Arial`, available in the local Word environment used for these samples. A different
  font or rendering engine can change page breaks and must be checked separately.
- Reconstruction notice on every page. The examples additionally say their data is fictional.
- Human-only sections are empty in the blank/short files. Longer fictional human-entered
  text in the long sample tests overflow; it is never derived from statements by the renderer.

The reconstruction deliberately regularizes the skewed scan's margins and does not attempt
to reproduce its exact ruled-paper line spacing. Whether the final accepted form needs a
continuous ruled background, repeat signature areas, or different margin/heading dimensions
should be settled during visual review, before application integration.

## Field ownership for later integration

| Input | Proposed source / rule |
|---|---|
| `institution_lines` | Reviewed template configuration; the sample follows the visible institutional heading |
| `subject` | Session subject proposed for human review |
| `session_date`, `opening_time`, `location` | Explicit session metadata, reviewed |
| `investigator`, `clerk`, statement speaker | Confirmed person/role bindings; no automatic signer inference |
| `referral` | Explicit entry; blank when unavailable |
| `statements[].kind` | Human-reviewed question, answer or independent statement |
| `statements[].text` | Reviewed transcript wording; line breaks and literal characters retained |
| `notes`, `conclusion`, `responsibilities`, `proposals`, `closing` | Explicit human input; empty by default |

The historical example's `س.ج` markers are not enough to reconstruct missing question text.
These specimens print `س` or `ج` only for actual supplied question/answer turns.

## Reproduce locally

Generate the Word documents with the existing cached dependency image, from the repository root:

```powershell
$m53Folder = (Resolve-Path -LiteralPath 'planning/report-template-m53').Path
docker run --rm --network none --read-only --cap-drop ALL --security-opt no-new-privileges --pids-limit 128 --memory 1g --cpus 2 --tmpfs /tmp:rw,size=268435456 -v "${m53Folder}:/work" --entrypoint python military-stt/report-tests:local /work/build_samples.py
```

Export using the locally installed Microsoft Word, then run the independent PDF checks:

```powershell
& planning/report-template-m53/convert_with_word.ps1
python planning/report-template-m53/verify_samples.py
```

The builder checks exact source paragraph preservation in each DOCX. The converter uses a
separate hidden Word instance, disables macros, opens only these generated files read-only,
saves each PDF to a fresh temporary path, validates it, and confirms the DOCX hash is unchanged.
It does not upload documents or call a model. This desktop export is for the review samples;
it is not a deployed backend converter.

The PDF checks compare the complete body character inventory (including punctuation) after
Unicode normalization and excluding whitespace/directional controls, check page counters,
check review notices, and check page boundaries. Word's Arabic PDF text extraction introduces
ligature-order/spacing artifacts, so these checks do not claim exact extracted word order.
DOCX source paragraphs are checked exactly, and all six resulting PDF pages were visually
reviewed. Right-to-left alignment and paragraph-break issues found during review were fixed.
Interactive editing/printing in Word and institutional template acceptance remain pending.

Technical references: [python-docx tables](https://python-docx.readthedocs.io/en/latest/api/table.html),
[Word PDF format](https://learn.microsoft.com/en-us/office/vba/api/word.wdsaveformat).
